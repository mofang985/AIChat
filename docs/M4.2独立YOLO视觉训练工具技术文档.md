# M4.2 独立 YOLO 视觉训练工具技术文档

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v0.1 |
| 编写日期 | 2026-07-30 |
| 所属阶段 | M4.2 YOLO / ONNX 视觉识别旁路验证 |
| 工具名称 | AIChat.VisionTrainer |
| 目标产物 | `wechat-layout.onnx`、`labels.txt`、`model-version.json` |

## 1. 背景与目标

当前 RPA 客户端已经接入 `YoloOnnxVisionDetector`，可以在 M4 单会话流程中旁路加载 ONNX 模型，对微信窗口进行视觉区域识别验证。但模型训练、截图采集、数据集整理和导出不应放进 RPA 客户端。

因此新增一个独立训练工具 `AIChat.VisionTrainer`，用于完成：

- 采集微信界面原始截图。
- 整理 YOLO 数据集目录。
- 校验图片与标签文件。
- 调用 Ultralytics YOLO 训练模型。
- 导出 ONNX 模型。
- 生成 RPA 客户端可直接加载的模型包。
- 预测测试截图并输出标注图，用于人工验收识别质量。

该工具只服务于模型训练与验证，不控制微信，不发送消息，不接入后端数据库。

## 2. 系统边界

`AIChat.VisionTrainer` 与 RPA 客户端职责分离：

| 模块 | 职责 |
| --- | --- |
| `AIChat.VisionTrainer` | 样本采集、数据集整理、标签校验、训练、导出、模型打包 |
| 标注工具 | 人工画框，推荐 CVAT 或 LabelImg |
| `AIChat.RpaClient` | 加载 `wechat-layout.onnx` 做本地旁路推理，输出对比调试图 |
| 后端 API | 不参与 M4.2 模型训练和推理 |

M4.2 不使用 YOLO 坐标执行真实点击或发送。只有 M4.3 验证稳定后，才考虑切换为 YOLO 优先、OpenCV 兜底。

## 5. 标签规范

第一版只识别微信单会话界面的 7 个目标，顺序必须固定：

```text
0 conversation_list
1 chat_content
2 input_area
3 input_box
4 send_button
5 customer_message_bubble
6 self_message_bubble
```

对应 `labels.txt`：

```text
conversation_list
chat_content
input_area
input_box
send_button
customer_message_bubble
self_message_bubble
```

M5.1 未读队列增强模型可在新版本中追加：

```text
7 unread_badge
8 conversation_list_item
```

追加标签必须生成新的候选模型版本，例如 `m5.1-yolo-unread-v1`，不得用旧 `m4.2-v2` 名称覆盖既有模型；RPA 端 `labels.txt` 必须与 ONNX 训练时的标签顺序完全一致。

对应 `data.yaml`：

```yaml
path: E:/Code/AIChat/datasets/wechat-layout
train: images/train
val: images/val
test: images/test

names:
  0: conversation_list
  1: chat_content
  2: input_area
  3: input_box
  4: send_button
  5: customer_message_bubble
  6: self_message_bubble
```

## 6. 样本采集规则

样本采集指保存**干净的微信客户端原始截图**，不是保存已经画了调试框的 `layout-captures` 或 `yolo-captures`。

采集范围：

- 官方微信 Windows 客户端。
- 微信窗口最大化。
- 截取完整微信客户区或完整微信窗口。
- 优先使用测试微信号和测试会话。
- 不采集真实客户隐私内容。

第一轮样本建议：

| 阶段 | 数量 | 用途 |
| --- | ---: | --- |
| POC | 100-200 张 | 验证 YOLO 能否识别微信区域 |
| 内测 | 300-500 张 | 训练初版可用模型 |
| 稳定 | 1000+ 张 | 覆盖多分辨率、多微信状态 |

必须覆盖的界面状态：

- 1920x1080，Windows 缩放 100%，微信最大化。
- 2560x1440，Windows 缩放 100%，微信最大化。
- 空输入框。
- 已输入待发送文本，发送按钮可见。
- 只有客户消息。
- 同时有客户消息和自己消息。
- 长消息、短消息、多行消息。
- 商品询价、售后咨询、普通问候等测试话术。

推荐命名规则：

```text
wechat_20260730_103012_1920x1080_empty_input.png
wechat_20260730_103045_1920x1080_send_button_visible.png
```

## 7. 标注规则

标注优先使用工具内置 Tkinter GUI，也可使用 CVAT 或 LabelImg。

标注原则：

- 每张图至少标注 `conversation_list`、`chat_content`、`input_area`、`input_box`。
- `send_button` 只有按钮可见时标注。
- 客户左侧消息气泡标 `customer_message_bubble`。
- 自己右侧消息气泡标 `self_message_bubble`。
- 大区域框要覆盖完整区域，不要只框标题或局部内容。
- 消息气泡框要尽量贴近气泡外边界，不包含头像和时间。

M5.1 追加标签标注原则：

- `unread_badge` 只框头像右上角的微信未读红点或红色数字角标，不框公众号封面、头像红色区域、红色昵称、红色摘要文字或搜索栏附近红色元素。
- `conversation_list_item` 若启用，应框整条会话行，从会话列表左边界到右边界，包含头像、昵称、摘要、时间和未读角标，但不包含上一行或下一行。
- 未读队列模型只用于只读候选定位；接入 RPA 前仍需保留 `SendMode=InputOnly` 和“不点击会话”的 M5.1 安全边界。
- 如果一张图有多条客户消息，应分别标注多个 `customer_message_bubble`。
- 如果消息被遮挡或显示不完整，仍按可见气泡区域标注。

YOLO 标签文件格式：

```text
class_id x_center y_center width height
```

后四个值为 0-1 的归一化比例。

示例：

```text
0 0.145000 0.500000 0.250000 0.960000
1 0.620000 0.420000 0.700000 0.620000
2 0.620000 0.865000 0.700000 0.220000
3 0.600000 0.850000 0.620000 0.120000
4 0.935000 0.930000 0.055000 0.035000
```

### 8.2 采集截图

从当前微信窗口采集原始截图：

```powershell
python -m aichat_vision capture --source wechat --out E:/Code/AIChat/datasets/wechat-layout/raw
```

如果截图缺少底部输入区，可先排查窗口匹配：

```powershell
python -m aichat_vision windows
```

多显示器或 4K 缩放环境下，可继续排查显示器坐标：

```powershell
python -m aichat_vision monitors
```

工具会在截图前启用 Windows Per-Monitor DPI awareness，避免 `GetWindowRect`、`ClientToScreen` 与 `ImageGrab` 在 4K 缩放、多屏坐标下使用不同坐标系。

然后优先使用完整窗口模式：

```powershell
python -m aichat_vision capture --source wechat --mode window --out E:/Code/AIChat/datasets/wechat-layout/raw --count 1
```

若完整窗口模式仍缺少底部输入区，可使用屏幕模式兜底：

```powershell
python -m aichat_vision capture --source wechat --mode screen --out E:/Code/AIChat/datasets/wechat-layout/raw --count 1
```

批量自动采集：

```powershell
python -m aichat_vision capture --source wechat --mode window --out E:/Code/AIChat/datasets/wechat-layout/raw --count 100 --interval 2
```

执行期间人工只需要切换测试聊天状态、滚动聊天记录、输入或清空测试文字，工具按间隔自动保存干净截图。

从已有图片目录导入：

```powershell
python -m aichat_vision capture --source-dir D:/wechat-screenshots --out E:/Code/AIChat/datasets/wechat-layout/raw
```

### 8.2.1 半自动预标注

为减少人工画框工作，工具提供预标注草稿命令：

```powershell
python -m aichat_vision prelabel --dataset E:/Code/AIChat/datasets/wechat-layout
```

默认只写入 4 个相对稳定的大区域：

- `conversation_list`
- `chat_content`
- `input_area`
- `input_box`

如果一批截图都确认发送按钮可见，可以额外加入：

```powershell
python -m aichat_vision prelabel --dataset E:/Code/AIChat/datasets/wechat-layout --include-send-button
```

预标注默认不覆盖已有 `.txt` 标签文件；如需重生成可追加 `--overwrite`。预标注不是最终标注，训练前仍必须人工复核，并补齐 `send_button`、`customer_message_bubble`、`self_message_bubble` 等变化较大的目标。

如果一张图的大区域已经人工修正，可以作为模板批量套用到其它 raw 图片：

```powershell
python -m aichat_vision template --dataset E:/Code/AIChat/datasets/wechat-layout --from-label E:/Code/AIChat/datasets/wechat-layout/raw/wechat_xxx.txt --overwrite
```

模板默认只复制 `conversation_list`、`chat_content`、`input_area`、`input_box`。如果同一批截图发送按钮位置稳定且都可见，可追加 `--include-send-button`。消息气泡仍需逐图人工补齐。

### 8.2.2 颜色规则自动补标

对于微信标准浅色主题，消息气泡和发送按钮可以先按颜色规则生成草稿标签。训练数据集 `raw` 使用：

```powershell
python -m aichat_vision autolabel --dataset E:/Code/AIChat/datasets/wechat-layout --dry-run
python -m aichat_vision autolabel --dataset E:/Code/AIChat/datasets/wechat-layout --overwrite
```

RPA 主动学习样本池使用：

```powershell
python -m aichat_vision autolabel-samples --source "$env:LOCALAPPDATA\AIChat\RpaClient\learning-samples" --dry-run
python -m aichat_vision autolabel-samples --source "$env:LOCALAPPDATA\AIChat\RpaClient\learning-samples" --overwrite
```

规则说明：

- 依赖已有 `chat_content` 和 `input_area` 大区域框，优先在区域内部搜索，降低误检。
- 在 `chat_content` 中按浅灰色气泡补 `customer_message_bubble`。
- 在 `chat_content` 中按绿色气泡补 `self_message_bubble`。
- 在 `input_area` 右下识别绿色发送按钮；空输入时浅灰按钮使用输入区右下相对位置兜底。
- 默认不覆盖已有人工框，只追加不重叠候选；需要重算 `send_button`、`customer_message_bubble`、`self_message_bubble` 时追加 `--overwrite`。

该命令仍属于半自动标注草稿，不替代 CVAT / LabelImg 人工复核。训练前建议抽查 10-20 张，重点修正误框和漏框。


### 8.2.3 YOLO 学习补录

当 `accepted` 中已经有一批人工确认正确的样本时，可以临时训练一个辅助 YOLO 模型，再用该辅助模型给目标分桶补录 `send_button`、`customer_message_bubble`、`self_message_bubble`。该辅助模型只用于写回 `.txt` 标签，不导出正式 ONNX，也不会替换 RPA 正式模型。

```powershell
python -m aichat_vision yolo-autolabel-samples --source "$env:LOCALAPPDATA\AIChat\RpaClient\learning-samples" --train-bucket accepted --target-bucket accepted --dry-run
python -m aichat_vision yolo-autolabel-samples --source "$env:LOCALAPPDATA\AIChat\RpaClient\learning-samples" --train-bucket accepted --target-bucket accepted --epochs 30 --imgsz 960 --batch 8 --device 0 --conf 0.35
```

说明：

- `--train-bucket` 是用于学习的已确认样本，默认 `accepted`。
- `--target-bucket` 是要补录的样本，默认 `accepted`。
- 默认只追加与已有框不重叠的预测框；需要覆盖三类旧自动框时，显式追加 `--overwrite-auto`。
- 训练产物写入 `artifacts/wechat-layout-yolo-autolabel/<version>/`。
- 该能力比颜色规则更慢，适合在人工修好一批样本后批量补录，不适合每次启动 RPA 自动执行。
### 8.3 校验标注

检查图片与标签是否一一对应、类别是否越界、坐标是否在 0-1 范围：

```powershell
python -m aichat_vision validate --dataset E:/Code/AIChat/datasets/wechat-layout
```

校验项：

- 图片是否可读取。
- 标签文件是否存在。
- `class_id` 是否在 0-6。
- 每行是否为 5 列。
- 坐标是否在 0-1。
- `width` / `height` 是否大于 0。
- 是否存在空标签。
- 是否存在未纳入 train / val / test 的文件。

### 8.4 划分数据集

将 raw 中已标注图片划分为 train / val / test：

```powershell

```

默认规则：

- 70% train。
- 20% val。
- 10% test。
- 使用固定随机种子，保证可复现。
- 图片和同名 `.txt` 标签一起移动或复制。

### 8.9 一键主动学习训练与候选升级

M4.3 在 RPA 本机学习样本池基础上提供一键主动学习训练命令。当前默认只纳入 `accepted` 样本，并在导入前自动补标 `send_button`、`customer_message_bubble`、`self_message_bubble`，避免图片中未标注的消息气泡被模型当背景学习；`review` 只建议人工清洗后显式使用 `--bucket review` 或 `--bucket all`。

训练前先检查是否达到 1000 张可用样本：

```powershell
python -m aichat_vision active-learn --source "$env:LOCALAPPDATA\AIChat\RpaClient\learning-samples" --dataset E:/Code/AIChat/datasets/wechat-layout --min-samples 1000 --review-count 50 --version sample-check --dry-run
```

该命令会预览训练前自动补标，不导入、不训练、不写模型。输出中重点看 `可用=<数量>`。`可用` 会排除重复图片、缺少同名 `.txt` 标签的图片和空标签图片；只有 `可用 >= 1000` 时才建议开始正式训练。

不足时会输出类似：

```text
错误：主动学习样本不足，暂不训练：当前可用=750，要求=1000。
```

达标时会输出类似：

```text
主动学习样本检查完成：扫描=1050, 可用=1008, 重复=20, 缺标签=10, 空标签=12
dry-run 模式：只完成样本检查，未导入、未训练、未写入产物。
```

如只想粗略查看截图数量，可用：

```powershell
$root = "$env:LOCALAPPDATA\AIChat\RpaClient\learning-samples"
(Get-ChildItem "$root\review","$root\accepted" -Filter *.png -File -ErrorAction SilentlyContinue).Count
```

粗略统计不判断标签和重复图片，正式训练前仍以 `active-learn --dry-run` 的 `可用` 数量为准。

确认样本达标后运行：

```powershell
python -m aichat_vision active-learn --source "$env:LOCALAPPDATA\AIChat\RpaClient\learning-samples" --dataset E:/Code/AIChat/datasets/wechat-layout --min-samples 1000 --review-count 50 --model yolo11n.pt --epochs 80 --imgsz 960 --batch 8 --device 0 --version m4.3-active-v1
```

该命令自动执行：

1. 对纳入分桶执行颜色规则自动补标，默认分桶为 `accepted`。
2. 统计可用样本，按图片 hash 去重。
3. 样本少于 `--min-samples` 时停止，不训练。
4. 导入 RPA 样本到 `dataset/raw`；若图片已存在，会同步更新同 hash 样本的 `.txt` 标签。
5. 生成复核抽样包：`E:/Code/AIChat/artifacts/wechat-layout-review/<version>/`。
6. 校验数据集并划分 train / val / test。
7. 调用 Ultralytics YOLO 训练，默认输出到 `tools/AIChat.VisionTrainer/runs/detect/<version>/`。
8. 对 test 集预测，输出到 `E:/Code/AIChat/artifacts/wechat-layout-predict/<version>/`。
9. 导出候选 ONNX，输出到 `E:/Code/AIChat/artifacts/wechat-layout-candidates/<version>/`。
10. 安装候选到 `%LOCALAPPDATA%\AIChat\RpaClient\models\wechat-layout-candidates\<version>\`。
11. 写入 `active-learn-report.json`。

候选目录包含：

```text
wechat-layout.onnx
labels.txt
model-version.json
best.pt
active-learn-report.json
```

安全自测可使用：

```powershell
python -m aichat_vision active-learn --source "$env:LOCALAPPDATA\AIChat\RpaClient\learning-samples" --dataset E:/Code/AIChat/datasets/wechat-layout --min-samples 1000 --review-count 50 --version m4.3-active-check --skip-train
```

确认预测效果后，再显式转正：

```powershell
python -m aichat_vision promote --candidate m4.3-active-v1 --install-local
```

`promote` 只复制候选目录中的 3 个正式运行文件：

```text
wechat-layout.onnx
labels.txt
model-version.json
```

`active-learn` 不覆盖正式模型目录；正式替换必须人工执行 `promote`。RPA 客户端不训练模型、不自动替换 ONNX，也不改变真实发送准入逻辑。

## 10. 验收标准

M4.2 不以真实发送成功作为验收标准，而以视觉识别质量作为验收标准。

第一轮验收：

- `conversation_list` 命中率不低于 90%。
- `chat_content` 命中率不低于 90%。
- `input_area` 命中率不低于 90%。
- `input_box` 命中率不低于 90%。
- `send_button` 在按钮可见时命中率不低于 90%。
- `customer_message_bubble` 与 `self_message_bubble` 能基本区分，命中率不低于 80%。
- 模型缺失、配置未开启、推理失败时，不影响 M4 主流程。
- RPA 客户端可以生成 YOLO 与 OpenCV 对比调试截图。

进入 M4.3 的条件：

- 至少覆盖 3 种分辨率或窗口尺寸。
- 输入框、发送按钮、聊天内容区识别明显优于 OpenCV 规则。
- YOLO 结果稳定，不出现大面积误检。
- 已有调试截图能支撑切换为 YOLO 优先。

## 11. 风险与处理

| 风险 | 处理 |
| --- | --- |
| 样本过少导致过拟合 | 第一轮至少 300 张内测样本，后续逐步扩充 |
| 标签顺序和 RPA 不一致 | 固定 `labels.txt`，工具 `validate` 校验类别范围 |
| 真实客户隐私泄露 | 只用测试号和测试话术采集；数据集不提交仓库 |
| 模型误检发送按钮 | M4.2 不直接使用 YOLO 坐标发送；M4.3 再加低置信度不发送策略 |
| 不同微信版本 UI 差异 | 采集样本时记录微信版本、分辨率、缩放比例 |
| CPU 训练速度慢 | POC 可 CPU 跑通，正式训练建议使用 NVIDIA GPU |

说明：

- 标注界面继续使用 CVAT 或 LabelImg，本工具只兼容其导出的 YOLO detect 文本格式。
- `capture --source wechat` 使用 `pywin32` 定位标题包含“微信”的可见窗口，再用 Pillow 截取客户区；该命令不会点击、输入或发送。
- `ingest-rpa` 用于导入 RPA 客户端本机主动学习样本；默认导入 `review` 分桶，支持 `--bucket accepted` 和 `--bucket all`。导入的是 OpenCV / YOLO 生成的草稿标签，训练前仍需要 LabelImg 或 CVAT 人工抽查修正。
- `active-learn` 默认纳入 `review + accepted`，样本数不足 `--min-samples` 时停止；达标后生成复核抽样包、训练、预测、导出候选并安装到 `wechat-layout-candidates\<version>`，不会覆盖正式模型目录。
- `promote --install-local` 只把候选目录中的 `wechat-layout.onnx`、`labels.txt`、`model-version.json` 复制到正式模型目录，不复制 `best.pt` 和 `active-learn-report.json`。
- `package --install-local` 只复制 `wechat-layout.onnx`、`labels.txt`、`model-version.json` 到 `%LOCALAPPDATA%\AIChat\RpaClient\models\wechat-layout\`，不修改 RPA 客户端配置和真实发送逻辑。
- 当前 v2 模型按 `imgsz=960` 导出，RPA 客户端 `YoloInputSize` 需要设置为 `960`。
- 训练数据、预测图和模型产物位于 `.gitignore` 忽略范围内，不应提交到仓库。
