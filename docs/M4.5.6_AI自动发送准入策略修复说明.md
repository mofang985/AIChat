# M4.5.6 AI 自动发送准入策略修复说明

## 背景

真实微信连续监听测试中，RPA 已经正确识别客户消息并生成 AI 回复，但没有执行发送。排查 `reply_suggestions` 后确认：模型返回的结构化 JSON 中 `RiskLevel=Low`，但 `ShouldAutoSend=false`，导致后端最终状态为 `ManualReviewRequired`，RPA 按安全规则跳过发送。

示例：

```json
{
  "CustomerQuestion": "我需要你帮我查询一下实时天气",
  "ReplyText": "您可以通过气象网站或 APP 查看青岛的实时天气情况哦。",
  "RiskLevel": "Low",
  "ShouldAutoSend": false
}
```

## 修复策略

后端新增安全能力边界回复兜底判断：当回复模式为 `LlmOnly`，最终风险为 `Low`，且后端来源安全规则允许时，如果模型误把“不能直接查询实时天气 / 建议客户查看天气 App 或气象网站”这类低风险能力边界回复标记为 `ShouldAutoSend=false`，后端可以改判为允许自动发送。

该兜底只覆盖能力边界回复，不放宽以下场景：

- 价格、库存、物流、售后、赔付、商品参数、活动优惠等业务事实或承诺。
- 回复中声称“我帮您查”“正在查询”“查询结果”等实际工具能力。
- `RiskLevel` 非 `Low`。
- 后端风险规则命中。
- RPA 输入框校验、发送前倒计时、`SendMode` 真实发送安全门或发送后校验未通过。

## 代码影响

- `AIChat.Application.AI.AiReplyModePolicy`
  - 新增 `CanOverrideModelAutoSendForSafeCapabilityBoundary`。
- `AIChat.Api.Endpoints.M3Endpoints`
  - 最终 `ShouldAutoSend` 使用 `effectiveModelAutoSend`，只对安全能力边界回复覆盖模型误判。
- `AIChat.UnitTests.AiReplyModePolicyTests`
  - 新增天气能力边界回复允许用例。
  - 新增“我帮您查”类能力冒充阻止用例。
