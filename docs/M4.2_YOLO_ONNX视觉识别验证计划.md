# M4.2 YOLO / ONNX 视觉识别验证计划

## 1. 阶段目标

M4.2 目标是在不影响当前 M4 单会话真实发送链路的前提下，验证 YOLO / ONNX 是否能更稳定地识别微信界面区域。

本阶段只做旁路验证：

- RPA 客户端继续使用当前 OpenCV 布局定位执行 OCR、输入和发送。
- YOLO / ONNX 只并行识别微信截图中的关键区域。
- YOLO 识别结果只保存到本机调试截图和本地日志。
- 暂不使用 YOLO 结果直接点击、输入或发送。

独立训练工具的详细设计见：


## 2. 识别目标

第一版建议标注并识别以下目标：

| 标签 | 说明 | M4.2 用途 |
| --- | --- | --- |
| `conversation_list` | 左侧会话列表区域 | 验证会话列表定位 |
| `chat_content` | 右侧聊天内容区 | 验证客户消息 OCR 裁剪区域 |
| `input_area` | 底部输入区整体 | 验证输入区分割稳定性 |
| `input_box` | 底部输入框 | 验证输入点击和输入校验区域 |
| `send_button` | 发送按钮 | 验证发送按钮坐标 |
| `customer_message_bubble` | 客户消息气泡 | 验证最新客户消息定位 |
| `self_message_bubble` | 自己发送的消息气泡 | 避免把自己消息当成客户消息 |

M5.1 可扩展：

- `unread_badge`：左侧会话列表头像右上角的未读红点或数字角标，用于替代纯颜色阈值，避免公众号封面、红色昵称、摘要高亮等红色元素误识别。
- `conversation_list_item`：单条会话行区域，可选；若只训练 `unread_badge`，RPA 仍可按会话列表行高推断候选行。

M6 可扩展：

- `friend_request_entry`
- `accept_friend_button`

## 3. 数据采集与标注

M4.2 第一轮数据量建议：

- 100-200 张截图：验证方案可行性。
- 300-500 张截图：训练一个可用于内测的初版模型。
- 1000 张以上：覆盖多分辨率、多缩放、多账号、多微信状态。

截图来源：

- 微信最大化，1920x1080，Windows 缩放 100%。
- 微信最大化，2560x1440，Windows 缩放 100%。
- 微信最大化，不同聊天内容状态：空输入框、已输入待发送、有客户消息、有自己消息、长消息、多条消息。
- 不保存真实客户隐私样本；采样时优先使用测试号和测试话术。

标注格式建议：

- 使用 YOLO 格式：`class x_center y_center width height`，坐标为归一化比例。
- 每张图对应一个 `.txt` 标签文件。
- 图片和标签不要提交真实客户敏感内容到仓库。
- 可先用独立工具 `prelabel` / `template` 生成大区域草稿，再用 `autolabel` 按微信颜色规则自动补 `send_button`、`customer_message_bubble`、`self_message_bubble`；自动补标后仍需人工抽查修正。

当前客户端已接入 `Microsoft.ML.OnnxRuntime 1.28.0` 作为本地推理依赖。`YoloModelPath` 为空时默认读取：


`YoloLabelsPath` 为空时默认读取同目录的 `labels.txt`；若文件不存在，则使用内置第一版标签清单。模型缺失、配置未开启或推理异常时，只写入日志，不影响 M4 当前 OpenCV 自动定位、OCR、输入和真实发送流程。

M4.2 客户端行为：

- 开始任务时截图微信客户区。
- 当前 OpenCV 布局检测照常执行。
- YOLO / ONNX 并行识别关键区域。
- 生成一张对比标注图：
  - OpenCV 结果：保持当前红 / 蓝 / 黄区域。
  - YOLO 结果：用另一组颜色标注模型识别框。
- 输出动作日志：YOLO 是否跳过、是否成功、命中数量、标签统计和调试截图路径。
- 不使用 YOLO 坐标执行真实点击。

调试截图路径建议：

```text
%LOCALAPPDATA%\AIChat\RpaClient\yolo-captures
```

## 6. 验收标准

M4.2 不以真实发送成功作为验收标准，而以识别质量作为验收标准。

第一轮可接受标准：

- `conversation_list`、`chat_content`、`input_area`、`input_box` 在测试截图中命中率不低于 90%。
- `send_button` 在输入框有待发送内容时命中率不低于 90%。
- `customer_message_bubble` 能区分客户消息和自己消息，命中率不低于 80%。
- YOLO 与 OpenCV 的关键区域差异可在调试图中直观看到。
- M5.1 若追加 `unread_badge`，测试截图中头像右上角未读角标召回率不低于 90%，红色头像/封面/昵称/摘要误识别率不高于 5%；该模型只允许驱动只读候选队列，不接管点击、输入或发送。
- 模型加载失败、模型文件缺失、推理异常时，不影响 M4 原有 OpenCV 执行链路。

进入 M4.3 的条件：

- 至少覆盖 3 种分辨率或窗口尺寸。
- 主要区域稳定命中。
- 发送按钮和输入框定位明显优于当前 OpenCV 规则。
- 已有调试截图能证明 YOLO 结果更可靠。

## 7. 后续 M4.3

M4.3 才考虑切换执行策略：

```text
YOLO 坐标优先
↓
OpenCV 布局规则兜底
↓
配置坐标最后兜底
↓
低置信度一律不发送
```

M4.2 阶段不直接替换当前 M4 自动发送链路。

M4.3 当前先落地主动学习样本池和离线候选升级流程：

- RPA 每轮任务只保存本机学习样本、metadata 和草稿 YOLO 标签。
- 训练前使用 `active-learn --dry-run` 检查可用样本数，只有去重后且具备非空同名 `.txt` 标签的图片才计入 `可用`。
- `AIChat.VisionTrainer active-learn` 默认只纳入 `accepted`，并在导入前自动补标 `send_button`、`customer_message_bubble`、`self_message_bubble`，随后在独立 Python 进程中一键完成样本导入、复核抽样包、校验、划分、训练、预测、ONNX 导出和候选安装。
- 候选模型默认安装到 `%LOCALAPPDATA%\AIChat\RpaClient\models\wechat-layout-candidates\<version>\`。
- 人工确认复核包和预测图后，显式执行 `promote` 才复制 3 个正式运行文件到 `%LOCALAPPDATA%\AIChat\RpaClient\models\wechat-layout\`。
- RPA 客户端不训练模型、不自动替换 ONNX，不改变真实发送准入逻辑。

## 8. 独立训练工具落地

M4.2 训练、导出和安装流程由独立 Python CLI 承担：

```text
tools/AIChat.VisionTrainer/
```

入口：

```powershell
cd E:\Code\AIChat\tools\AIChat.VisionTrainer
python -m aichat_vision --help
```

本机 GUI 入口：

```powershell
python -m aichat_vision gui
```

GUI 提供状态总览、内置样本标注、自动补录、主动学习训练和候选转正，减少手动输入命令。

核心命令：

- `init`：生成默认数据集目录、固定顺序 `labels.txt` 和 `data.yaml`。
- `capture`：采集微信原始截图，支持 `--count` 和 `--interval` 批量自动截图，或从已有截图目录导入。
- `prelabel`：为 raw 截图生成第一版大区域预标注草稿，减少人工画框工作。
- `autolabel` / `autolabel-samples`：在已有大区域框内按浅灰/绿色气泡和发送按钮位置自动补标 4/5/6 三类草稿标签；`autolabel-samples` 面向 RPA learning-samples，默认处理 `accepted`。
- `yolo-autolabel-samples`：用已确认样本临时训练辅助 YOLO，再补录 RPA learning-samples；只写回 `.txt` 标签，不替换正式 ONNX。
- `gui`：启动 Windows 本机 Tkinter GUI，集成状态总览、内置标注器、主动学习训练和候选转正。
- `validate`：校验 YOLO 图片和标签文件。
- `split`：按固定随机种子划分 train / val / test。
- `train`：调用 Ultralytics YOLO 训练。
- `predict`：输出预测可视化图，供人工验收。
- `export`：导出 `wechat-layout.onnx`，生成 `model-version.json`。
- `package`：安装模型包到 `%LOCALAPPDATA%\AIChat\RpaClient\models\wechat-layout\`。
- `ingest-rpa`：导入 RPA 主动学习样本到训练数据集。
- `active-learn`：一键执行主动学习训练管道并安装候选模型。
- `promote`：人工确认候选效果后，将候选模型转正到正式模型目录。

该工具不调用后端 API，不新增数据库，也不修改 RPA 客户端真实发送链路。详细命令见 `tools/AIChat.VisionTrainer/README.md`。
