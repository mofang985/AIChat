## 1. 产品背景

当前业务存在 30 个店内员工个人微信工作号，主要用于直播引流承接、客户产品咨询、售后沟通和朋友圈运营。

直播部门在直播过程中引导客户添加员工个人微信号。客户添加后，如果员工响应不及时，可能导致客户流失。日常咨询中，员工需要频繁回答价格、规格、发货、使用方法、售后规则等重复问题，回复效率和话术一致性较难保证。

本 MVP 目标是在不改变现有个人微信工作号使用习惯的前提下，提供一个有人值守的全视觉 RPA AI 客服助手。系统在员工启动和监督下自动识别微信界面、处理好友申请、发送欢迎语、读取客户消息、生成 AI 回复并顺序执行发送；员工负责观察运行状态、审核关键内容、暂停异常任务和人工接管高风险会话。

## 2. 产品定位

本产品第一版定位为：

> 面向个人微信工作号的有人值守全视觉 RPA AI 客服助手。

系统不以无人值守自动化为首发目标，而是优先实现员工在岗监督下的自动执行：

- 新好友申请识别与顺序处理。
- 欢迎语生成与自动发送。
- 客户消息全视觉识别。
- AI 回复生成、审核停顿与自动发送。
- 多客户会话单线程队列处理。
- 回复发送频率控制。
- 高风险问题拦截。
- 员工随时暂停、终止和接管。
- 客服处理记录留存。

## 3. 合规与风险边界

个人微信客户端并非官方客服开放平台，使用 RPA 或客户端自动化存在账号限制、功能限制或封号风险。

MVP 必须遵守以下边界：

- 不使用微信协议逆向。
- 不读取微信本地数据库。
- 不使用 Hook、DLL 注入、外挂、多开器或模拟器。
- 不绕过微信安全策略。
- 不设计用于规避平台风控的随机点击、账号轮换、批量行为伪装等能力。
- 不做脱离员工监督的大批量加好友、营销式批量通过、批量群发。
- 不做脱离员工值守的无人化运行。
- 不做高风险内容自动发送。
- 不承诺可以避免封号或平台限制。

MVP 允许做的方向：

- 基于本地窗口可见信息进行全视觉识别。
- 员工启动任务后，RPA 在前台可见窗口中自动执行点击、输入和发送。
- 员工在设备前监督运行，并可以随时暂停、停止或人工接管。
- 自动处理好友申请和欢迎语发送，但必须受任务数量、频率和异常停止规则约束。
- 自动回复低风险客户消息，但必须受意图白名单、置信度、风险规则和发送频率约束。
- 多个客户同时来消息时，进入单线程队列顺序处理，不并发操作多个会话。
- 记录系统内的处理结果。
- 通过业务规则限制高风险回复。

### 3.1 MVP 默认部署方式

为节约硬件成本，MVP 默认采用：

```text
一台高配物理主机
↓
多个独立 Windows 虚拟机
↓
每个虚拟机绑定一名员工
↓
每个虚拟机登录一个个人微信工作号
↓
每个虚拟机运行一个 RPA 客户端实例
```

部署边界：

- 不在同一个 Windows 系统中多开多个微信客户端。
- 不使用微信多开器、模拟器、插件或非官方客户端。
- 每个虚拟机内只运行一个微信客户端和一个 RPA 客户端。
- 每个虚拟机的自动化任务、OCR 文本、AI 回复、风险记录和动作日志相互隔离。
- 员工必须能独立监督自己负责的虚拟机，并能随时暂停、终止或接管任务。

## 4. 目标用户

### 4.1 店主 / 管理者

关注点：

- 直播引流客户是否能及时承接。
- 员工回复是否及时、统一、专业。
- 是否能减少重复咨询成本。
- 是否能控制个人微信账号风险。
- 是否能查看客户咨询和员工处理情况。

### 4.2 直播运营人员

关注点：

- 直播间导流后是否有人及时接待。
- 不同直播场次是否可以使用不同欢迎语。
- 是否能识别客户来源和意向商品。

### 4.3 一线客服 / 员工

关注点：

- 新好友申请是否能及时提醒。
- 是否能快速生成欢迎语和产品回复。
- 是否减少手动点击、输入话术、查资料和重复发送的时间。
- 遇到售后纠纷时是否有风险提醒。
- 是否能在自动化执行异常时快速暂停或接管。

## 5. MVP 目标

MVP 阶段验证以下问题：

- 有人值守 RPA 自动执行是否能提高员工客服回复效率。
- 商品资料、FAQ 和售后规则是否能支撑常见问题回复。
- 新好友申请自动处理和欢迎语自动发送是否能减少直播引流客户流失。
- 风险拦截是否能避免 AI 生成不适合发送的话术。
- 单线程多会话队列和发送频率控制是否符合员工实际监督习惯。
- 个人微信工作号场景下的有人值守自动化工具是否能被员工接受。

## 6. MVP 非目标

MVP 阶段暂不做：

- 不做脱离员工监督的无人值守自动通过好友。
- 不做脱离员工监督的无人值守自动发送消息。
- 不做朋友圈自动发布。
- 不做微信群群发、拉群、自动加群。
- 不做微信协议逆向或非授权消息接口。
- 不做完整 CRM。
- 不做订单、退款、赔偿、补发等自动操作。
- 不做多平台统一客服接入。

## 7. 核心业务场景

### 7.1 直播引流客户承接

客户在直播间看到引导信息后，添加某个员工个人微信工作号。

MVP 支持：

- 通过全视觉识别待处理好友申请。
- 员工启动任务后，按配置数量顺序自动通过好友申请。
- 按直播场次、商品、活动生成欢迎语。
- 在发送前展示短暂停顿，留给值守员工观察和终止。
- 在员工监督下自动输入并发送欢迎语。
- 记录客户来源、处理时间和负责员工。

### 7.2 产品咨询回复

客户询问产品价格、规格、尺码、成分、适用人群、发货时间、活动等问题。

MVP 支持：

- 本地助手通过截图、OCR 和界面定位读取当前可见客户消息。
- 系统识别客户意图。
- 检索商品资料和 FAQ。
- 生成 1-3 条回复候选，并选择符合规则的一条作为待发送回复。
- 展示引用来源和风险提示。
- 在发送前停顿展示待发送内容，留给值守员工审核。
- 低风险问题在员工监督下自动输入并发送。
- 多个客户同时发来消息时，系统按单线程队列顺序处理。

### 7.3 售后与投诉处理

客户咨询退换货、质量问题、破损、赔偿、投诉、差评等问题。

MVP 支持：

- 识别高风险意图。
- 生成安抚和引导话术。
- 明确提示必须人工处理。
- 不生成直接承诺退款、赔偿、补发的回复。
- 记录转人工原因。

### 7.4 多会话单线程处理

多个客户同时发送消息时，系统不得并发操作多个微信会话，而是将待处理会话放入单线程队列。

MVP 支持：

- 扫描当前微信会话列表中的未读会话。
- 将客户 A、客户 B、客户 C 等待处理消息加入队列。
- 按队列顺序逐个打开会话、识别消息、生成回复、发送或转人工。
- 每次只操作一个微信窗口和一个会话。
- 当前会话处理完成或进入人工接管后，才处理下一个会话。
- 发送前必须等待配置的审核停顿时间。
- 两次发送之间必须满足配置的最小发送间隔。

业务规则：

- 不做多线程并发发送。
- 不在同一时间操作多个微信号或多个会话。
- 会话对象识别不确定时必须停止当前任务。
- OCR 置信度低于阈值时必须停止当前任务。
- 当前会话出现高风险意图时，标记转人工并跳过自动发送。

### 7.5 朋友圈运营素材辅助

员工每天需要发布朋友圈内容，用于产品种草、活动提醒和客户维护。

MVP 支持：

- 根据商品资料生成朋友圈文案草稿。
- 支持不同风格：种草、活动、专业说明、客户案例。
- 管理员审核素材。
- 员工手动发布。

MVP 不支持自动发布朋友圈。

## 8. 功能需求

### 8.1 员工工作号管理

#### 功能说明

管理店内员工和其对应的个人微信工作号信息。

#### 功能项

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 员工账号管理 | P0 | 维护员工姓名、岗位、负责业务 |
| 微信工作号登记 | P0 | 记录微信昵称、备注、所属部门 |
| 工作号状态 | P1 | 正常、暂停接待、离职停用 |
| 客户端使用授权 | P0 | 设置员工是否允许使用 RPA 客户端 |
| 客户端使用期限 | P0 | 设置授权开始时间、结束时间，过期后禁止登录和启动任务 |
| 离职禁用 | P0 | 员工离职或停用后，立即禁用其 RPA 客户端使用权限 |
| 接待上限配置 | P1 | 配置每日建议新增客户数量，用于内部运营控制 |

#### 业务规则

- 微信工作号仅作为内部管理字段，不保存微信登录凭证。
- 系统不代替员工登录个人微信。
- 离职或停用员工不再分配客户，不允许登录 RPA 客户端，不允许启动自动化任务。
- RPA 客户端启动、心跳和创建任务时，必须校验员工授权状态和使用期限。
- 当前时间早于授权开始时间或晚于授权结束时间时，客户端不得继续执行任务。
- 管理员在 Web 后台禁用员工后，运行中的 RPA 任务应在下一次心跳或配置刷新时停止。

### 8.2 好友申请有人值守自动处理

#### 功能说明

帮助员工在设备前监督 RPA 自动处理直播引流产生的新好友申请。

#### 功能项

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 好友申请视觉识别 | P0 | 识别微信界面中的待处理好友申请 |
| 有人值守自动通过 | P0 | 员工启动任务后，按配置数量顺序通过好友申请 |
| 客户来源标记 | P0 | 支持选择直播场次、商品、活动来源 |
| 欢迎语生成 | P0 | 根据来源和商品生成欢迎语 |
| 欢迎语自动发送 | P0 | 通过好友后，在员工监督下自动输入并发送欢迎语 |
| 审核停顿 | P0 | 发送前停顿指定秒数，允许员工终止 |
| 处理状态记录 | P1 | 待处理、已通过、已忽略、需跟进 |
| 异常停止 | P1 | 识别异常、窗口变化或数量超限时停止任务 |

#### 业务规则

- 好友申请自动通过必须由员工手动启动任务。
- 自动执行期间员工必须在设备前监督。
- 单次任务最多处理配置数量的好友申请。
- 通过好友和发送欢迎语必须顺序执行，不并发操作。
- 欢迎语发送前必须展示审核停顿。
- 员工可通过按钮或快捷键随时暂停、终止或接管。
- 欢迎语不得包含虚假承诺、夸大宣传或诱导违规内容。

### 8.3 商品资料库

#### 功能说明

维护产品基础资料，为 AI 回复提供依据。

#### 功能项

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 新增商品 | P0 | 维护商品名称、类目、价格说明、卖点 |
| 商品详情 | P0 | 维护适用人群、规格、使用方法、注意事项 |
| 发货规则 | P0 | 维护发货时间、快递说明、偏远地区说明 |
| 商品状态 | P1 | 启用、停用 |
| 素材标签 | P1 | 支持直播款、主推款、活动款等标签 |

#### 业务规则

- AI 不得编造商品资料中没有的信息。
- 商品停用后不应参与回复生成。
- 价格和活动信息必须有明确有效期或备注。

### 8.4 FAQ 知识库

#### 功能说明

维护高频问题和标准答案。

#### 功能项

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 新增 FAQ | P0 | 维护问题、标准答案、适用商品 |
| FAQ 分类 | P0 | 售前、发货、活动、使用、售后 |
| 启停状态 | P0 | 控制是否参与 AI 回复 |
| 相似问法 | P1 | 支持同一答案对应多个问法 |
| 命中统计 | P2 | 统计高频问题 |

#### 业务规则

- FAQ 命中优先级高于通用模型回答。
- 过期活动 FAQ 必须停用。
- 信息不足时应提示员工补充资料。

### 8.5 AI 回复建议

#### 功能说明

根据客户问题、商品资料、FAQ 和售后规则生成客服回复建议。

#### 功能项

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 消息视觉识别 | P0 | 通过截图、OCR 和界面定位读取当前可见客户消息 |
| 意图识别 | P0 | 输出咨询类型、置信度、风险等级 |
| 回复生成 | P0 | 生成 1-3 条回复候选，并选择符合规则的一条待发送 |
| 引用来源 | P0 | 展示命中的商品资料或 FAQ |
| 发送前审核停顿 | P0 | 自动输入或发送前停顿指定时间，允许员工终止 |
| 有人值守自动发送 | P0 | 低风险回复在员工监督下自动输入并发送 |
| 回复重写 | P1 | 支持调整语气或重新生成 |
| 快捷话术 | P1 | 支持收藏常用回复 |

#### 业务规则

- 回复必须适合微信聊天语境。
- 回复不得承诺退款、赔偿、补发结果。
- 回复不得包含绝对化宣传、医疗功效承诺等高风险内容。
- 高风险问题只生成安抚和转人工建议。
- 低风险自动发送必须满足意图白名单、置信度阈值、风险检测通过和发送频率限制。
- 发送前必须保留审核停顿时间，员工可随时终止。
- 多个会话同时有消息时，必须进入单线程队列顺序处理。

### 8.6 风险控制

#### 功能说明

识别客户问题和 AI 回复中的风险，防止员工误发不合适内容。

#### 风险类型

| 风险类型 | 示例 |
| --- | --- |
| 退款承诺 | 一定给您退款 |
| 赔偿承诺 | 我们赔您 100 元 |
| 补发承诺 | 马上给您补发 |
| 投诉威胁 | 不处理我就投诉 |
| 情绪激烈 | 骂人、威胁差评、强烈不满 |
| 法律风险 | 律师、起诉、监管投诉 |
| 绝对化宣传 | 全网最低、保证有效 |
| 功效承诺 | 一定治好、保证见效 |

#### 功能项

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 敏感词检测 | P0 | 检查客户问题和 AI 回复 |
| 高风险意图识别 | P0 | 退款、赔偿、投诉等转人工 |
| 风险原因提示 | P0 | 告诉员工为什么不建议发送 |
| 风险规则维护 | P1 | 管理员维护敏感词和风险规则 |
| 人工接管标记 | P1 | 标记该客户需人工处理 |

### 8.7 朋友圈文案辅助

#### 功能说明

为员工生成朋友圈运营文案草稿。

#### 功能项

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 文案生成 | P1 | 根据商品资料生成朋友圈文案 |
| 风格选择 | P1 | 种草、活动、专业说明、客户案例 |
| 素材审核 | P1 | 管理员审核后员工使用 |
| 文案库 | P2 | 保存历史朋友圈文案 |

#### 业务规则

- MVP 不自动发布朋友圈。
- 文案不得包含违规夸大、虚假宣传、绝对化用语。
- 员工需要自行确认并手动发布。

### 8.8 处理记录与统计

#### 功能说明

记录客户咨询、AI 回复建议、员工处理状态和风险结果。

#### 功能项

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 问答记录 | P0 | 保存客户问题和 AI 回复 |
| 采纳状态 | P1 | 记录回复是否被员工使用 |
| 风险记录 | P1 | 保存风险检测结果 |
| 员工处理统计 | P1 | 查看每个员工处理量 |
| 客户来源统计 | P2 | 按直播场次、商品、活动统计 |

#### 业务规则

- 不保存微信登录凭证。
- 不明文保存敏感密钥。
- 客户手机号、地址等敏感信息需要脱敏展示。
- 管理员可查看统计，一线员工只能查看自己负责的数据。

### 8.9 全视觉 RPA 执行引擎

#### 功能说明

通过全视觉方式识别微信 Windows 客户端界面，并在员工监督下执行点击、输入、发送和会话切换。

#### 功能项

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 微信窗口识别 | P0 | 定位微信主窗口、会话列表、聊天区、输入框 |
| 截图与 OCR | P0 | 识别会话昵称、未读标记、客户消息和好友申请 |
| 单线程任务队列 | P0 | 多个客户会话按队列顺序处理 |
| 发送频率控制 | P0 | 控制两次发送之间的最小间隔 |
| 审核停顿控制 | P0 | 每次通过好友或发送消息前停顿 |
| 鼠标点击模拟 | P0 | 按任务步骤点击会话、好友申请按钮、输入框、发送按钮等界面元素 |
| 键盘输入模拟 | P0 | 在输入框获得焦点后，通过键盘输入或快捷键完成消息编写 |
| 动作序列编排 | P0 | 将点击、输入、发送、等待、校验编排为可执行步骤 |
| 紧急停止 | P0 | 支持界面按钮和全局快捷键停止 |
| 异常检测 | P0 | 窗口丢失、焦点错误、OCR 低置信度、会话变化时停止 |
| 执行动作日志 | P1 | 记录点击、输入、发送、停止原因 |

#### 业务规则

- RPA 只操作前台可见的微信窗口。
- 自动化任务必须复现员工原本的前台操作路径，包括鼠标点击、输入框聚焦、键盘输入和发送动作。
- 消息编写阶段必须先定位并点击微信输入框，再通过键盘输入内容，不得跳过输入框状态校验。
- 发送动作可以配置为点击发送按钮或使用键盘快捷键，但执行前必须确认会话对象和待发送内容。
- 鼠标点击和键盘输入动作之间需要保留界面响应等待时间。
- 动作等待时间用于保证界面稳定和员工监督，不用于规避平台风控。
- 同一时间只允许一个 RPA 任务运行。
- 同一时间只允许处理一个客户会话。
- 会话对象识别不确定时不得发送。
- 输入框定位不确定时不得发送。
- OCR 置信度低于阈值时不得发送。
- 发送内容和目标会话必须在发送前进入审核停顿。
- 连续异常达到阈值后自动停止整轮任务。
- 员工手动移动鼠标、切换窗口或触发暂停时，任务必须进入暂停状态。

### 8.10 自动化功能配置中心

#### 功能说明

所有自动化能力都必须可配置，管理员或员工可以按功能、账号和时间段控制是否启用、暂停或关闭。

#### 功能项

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 功能总开关 | P0 | 控制某项自动化能力是否允许运行 |
| 运行状态 | P0 | 支持开启、暂停、关闭 |
| 生效时间段 | P0 | 配置每日开始时间和结束时间 |
| 适用工作号 | P0 | 配置哪些个人微信工作号启用该功能 |
| 任务上限 | P0 | 配置单次、每日处理数量上限 |
| 频率限制 | P0 | 配置发送前审核停顿和最小发送间隔 |
| 风险规则绑定 | P0 | 配置该功能适用的风险规则 |
| 人工接管策略 | P1 | 配置异常、高风险、低置信度时的处理方式 |
| 配置变更记录 | P1 | 记录谁在何时修改了配置 |

#### 可配置自动化能力

| 自动化能力 | MVP 默认状态 | 可配置项 |
| --- | --- | --- |
| 好友申请自动处理 | 关闭 | 开启 / 暂停 / 关闭、开始时间、结束时间、单次上限、每日上限 |
| 欢迎语自动发送 | 关闭 | 开启 / 暂停 / 关闭、模板、审核停顿、发送间隔、适用来源 |
| 客户消息自动回复 | 关闭 | 开启 / 暂停 / 关闭、意图白名单、置信度阈值、审核停顿、发送间隔 |
| 高风险自动拦截 | 开启 | 风险词、风险意图、转人工策略 |
| 多会话队列处理 | 开启 | 单轮会话上限、队列顺序、异常停止阈值 |
| 朋友圈文案生成 | 开启 | 文案风格、适用商品、审核要求 |

#### 业务规则

- 所有自动化功能默认关闭，由管理员或员工主动开启。
- 开启自动化功能时必须设置生效时间段。
- 当前时间不在生效时间段内时，不得自动执行。
- 暂停状态下保留配置，但不执行自动化动作。
- 关闭状态下不扫描、不入队、不执行。
- 配置修改后，对新任务立即生效；运行中的任务可按规则暂停或完成当前会话后生效。
- 员工手动暂停优先级高于系统配置。
- 高风险自动拦截不允许关闭，只允许调整规则内容和提示方式。

### 8.11 AI 大模型接入服务

#### 功能说明

系统需要接入 AI 大模型，用于意图识别、回复生成、欢迎语生成、朋友圈文案生成、风险复核和回复改写。大模型能力应独立封装，避免业务代码直接绑定某一家供应商。

#### 功能项

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 模型供应商配置 | P0 | 支持配置 OpenAI Compatible、Azure OpenAI、DeepSeek、通义、智谱等供应商 |
| 模型用途配置 | P0 | 按意图识别、回复生成、风险复核、文案生成分别选择模型 |
| API 密钥管理 | P0 | 密钥加密存储，日志中不得明文输出 |
| Prompt 模板管理 | P0 | 管理系统提示词、回复格式、风险约束和店铺语气 |
| 结构化输出 | P0 | AI 输出必须包含意图、置信度、风险等级、回复内容、引用来源 |
| 调用超时控制 | P0 | 配置单次调用超时时间 |
| 失败重试与降级 | P1 | 调用失败时重试，仍失败则使用 FAQ 标准答案或转人工 |
| Token 与成本记录 | P1 | 记录每次调用的 token、耗时、模型和费用估算 |
| AI 调用审计 | P1 | 记录输入摘要、输出摘要、风险结果和任务来源 |

#### 业务规则

- AI 服务层必须通过统一接口调用模型，不允许在业务流程中直接拼接供应商 API。
- 不同能力可以使用不同模型，例如意图识别使用低成本模型，回复生成使用质量更高的模型。
- 模型输出必须经过 JSON 或结构化格式解析，不得只依赖纯文本结果。
- AI 回复必须经过知识库约束和风控复核后，才允许进入 RPA 自动发送流程。
- 未命中知识库或知识库置信度不足时，不得编造答案，应转人工或生成追问话术。
- AI 调用失败、超时或结构化解析失败时，不得自动发送。
- API Key、Endpoint、Secret 等敏感配置必须加密保存，不得写入普通日志。

#### 模型供应商抽象

```text
ILlmProvider
├─ OpenAICompatibleProvider
├─ AzureOpenAIProvider
├─ DeepSeekProvider
├─ TongyiProvider
└─ ZhipuProvider
```

统一请求结构：

| 字段 | 说明 |
| --- | --- |
| ProviderCode | 模型供应商 |
| ModelName | 模型名称 |
| Scenario | 调用场景：意图识别、回复生成、风险复核、文案生成 |
| PromptTemplateCode | Prompt 模板编码 |
| UserInput | 客户问题或文案生成要求 |
| Context | 店铺、商品、FAQ、售后规则、历史消息等上下文 |
| Temperature | 生成随机性 |
| MaxTokens | 最大输出 token |
| TimeoutSeconds | 超时时间 |

统一响应结构：

| 字段 | 说明 |
| --- | --- |
| Success | 是否调用成功 |
| Intent | 识别意图 |
| Confidence | 置信度 |
| RiskLevel | 风险等级 |
| ReplyContent | 回复内容 |
| SourceRefs | 引用来源 |
| RiskWarnings | 风险提示 |
| NeedHumanReview | 是否需要人工审核 |
| ErrorCode | 失败编码 |
| ErrorMessage | 失败原因 |
| TokenUsage | Token 使用量 |

### 8.12 知识库与 RAG 检索服务

#### 功能说明

知识库用于约束 AI 回复，避免模型编造商品、价格、活动、发货、售后等信息。MVP 阶段知识库优先覆盖商品资料、FAQ、售后规则、直播活动话术和朋友圈素材。

#### 知识库类型

| 类型 | 优先级 | 说明 |
| --- | --- | --- |
| 商品知识 | P0 | 商品名称、卖点、规格、价格说明、适用人群、使用方法、注意事项 |
| FAQ 知识 | P0 | 高频问题、标准答案、相似问法、适用商品 |
| 售后规则 | P0 | 退换货、破损、错发、漏发、质量问题处理规则 |
| 直播活动话术 | P1 | 直播场次、优惠活动、赠品、限时说明 |
| 风险规则知识 | P1 | 禁止承诺、禁用词、平台敏感表达 |
| 朋友圈素材知识 | P1 | 商品种草点、活动信息、客户案例素材 |

#### 功能项

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 知识录入 | P0 | 支持后台手动维护商品、FAQ、售后规则 |
| 知识启停 | P0 | 停用知识不得参与检索和回复生成 |
| 知识有效期 | P0 | 活动、价格、赠品等信息必须支持有效期 |
| 知识分片 | P0 | 将长文本拆分为可检索的知识片段 |
| 关键词检索 | P0 | MVP 可先用关键词和分类匹配保证可控 |
| 向量检索 | P1 | 支持 Embedding 后进行语义召回 |
| 混合检索 | P1 | 结合关键词、分类、商品、向量相似度召回 |
| 引用来源 | P0 | 回复必须展示命中的知识来源 |
| 命中置信度 | P0 | 输出知识命中分数，用于自动发送决策 |
| 知识缺口记录 | P1 | 未命中时记录问题，供管理员补充知识 |

#### RAG 处理流程

```text
客户消息
↓
消息清洗与敏感信息脱敏
↓
意图识别和商品/场景识别
↓
检索商品资料 / FAQ / 售后规则 / 活动话术
↓
筛选高相关知识片段
↓
构造 Prompt 上下文
↓
调用大模型生成结构化回复
↓
风险复核
↓
输出回复内容、引用来源、风险提示和自动发送建议
```

#### 业务规则

- FAQ 标准答案优先级高于大模型自由生成。
- 售后规则优先级高于普通商品说明。
- 活动、价格、赠品等信息必须在有效期内才可参与回复。
- 未命中可信知识来源时，不得自动发送。
- 商品状态为停用时，该商品知识不得参与检索。
- 每条自动发送的 AI 回复必须保存引用来源。
- 知识库变更后，需要重新生成检索索引或标记待同步。
- MVP 可以先实现关键词检索，架构上预留向量检索和混合检索。

## 10. 业务流程

### 10.1 自动化任务启动校验流程

```text
员工点击启动某项自动化任务

↓
判断状态是否为开启
↓
判断当前时间是否在开始时间和结束时间内

判断当前工作号是否在适用范围内

不满足：拒绝启动并提示原因
```

### 10.2 好友申请有人值守自动处理流程

```text
客户添加员工个人微信
↓
员工打开微信并启动好友申请处理任务
↓
系统识别待处理好友申请
↓
员工选择客户来源 / 商品 / 活动
↓
系统生成欢迎语
↓
系统展示发送前审核停顿
↓
员工未终止：RPA 点击通过好友按钮
↓
RPA 点击聊天输入框
↓
RPA 通过键盘输入欢迎语
↓
系统校验输入框内容
↓
RPA 点击发送按钮或触发发送快捷键
员工终止：任务暂停或人工接管
↓
系统记录处理状态
```

### 10.3 多会话 AI 自动回复流程

```text
客户 A / B / C 发送咨询消息
↓
系统扫描微信会话列表未读状态
↓
按发现顺序加入单线程处理队列
↓
打开队首客户会话
↓
OCR 识别客户最新消息
↓
识别意图、置信度和风险等级
↓

↓
生成待发送回复
↓
执行风险检测
↓
低风险：进入发送前审核停顿
高风险：标记转人工并跳过自动发送
↓
员工未终止：RPA 点击会话并点击输入框
↓
RPA 通过键盘输入待发送回复

↓

↓

↓
记录问答、发送结果和风险结果
↓

```

### 10.4 AI 回复生成与知识库检索流程

```text
OCR 识别客户最新消息
↓
清洗文本并脱敏敏感信息
↓
调用意图识别模型
↓
识别商品、场景、意图、置信度和初始风险等级
↓
检索商品资料 / FAQ / 售后规则 / 活动话术
↓

↓
达标：构造 Prompt 并调用回复生成模型

↓

↓

↓

```

### 10.5 单线程队列处理逻辑

M5.1 当前落地“扫描未读会话 → 生成可见候选队列”的只读观察能力；M5.2 增加候选行 OCR，只读展示会话名、最新消息摘要、时间和未读数字；M5.3 增加连续扫描稳定性预演，只标记“观察中 / 可切换候选”；M5.4 增加员工显式触发的首个可切换候选受控切换，点击后只校验右侧聊天标题。RPA 客户端仍不锁定队首会话做自动处理、不输入、不发送、不调用 AI 回复。下面完整队列处理流程仍是后续 M5 目标。

```text
扫描未读会话
↓
生成待处理队列
↓
锁定队首会话
↓
识别会话对象和最新消息
↓
判断是否满足自动处理条件
↓
满足：审核停顿后执行
不满足：标记异常或转人工
↓
释放当前会话锁
↓
处理下一个会话
```

队列规则：

- 队列先进先出。
- 同一客户连续多条消息合并为一次处理上下文。
- 当前会话未完成前不切换到下一个会话。
- 会话识别不确定时停止当前任务。
- 单轮处理数量达到上限后停止，等待员工再次启动。

### 10.6 自动化暂停与关闭流程

```text
员工或管理员将功能状态改为暂停 / 关闭
↓
系统检查是否存在运行中任务
↓
暂停：当前动作完成后暂停队列，不再处理下一项
关闭：立即停止扫描和新任务创建，运行中任务进入停止流程
↓
记录配置变更和任务停止原因
```

### 10.7 售后高风险流程

```text
客户提出退款 / 赔偿 / 投诉 / 差评威胁
↓
系统识别高风险意图
↓
停止自动发送
↓
生成安抚和收集信息话术供员工参考
↓
提示员工不得直接承诺处理结果
↓
标记人工接管
↓
记录风险原因
```

### 10.8 异常停止流程

```text
RPA 执行过程中出现异常
↓
窗口焦点丢失 / OCR 低置信度 / 会话变化 / 输入框定位失败 / 员工触发暂停
↓
立即停止当前动作
↓
保留当前上下文和截图
↓
提示员工检查
↓
记录异常原因和任务状态
```

## 12. MVP 验收标准

### 12.1 功能验收

MVP 完成时应满足：

- 可以维护员工和个人微信工作号登记信息。
- 可以维护商品资料。
- 可以维护 FAQ。
- 可以维护售后规则和风险词。
- 可以配置 AI 大模型供应商、模型用途和 API 密钥。
- 可以维护 Prompt 模板和模板版本。
- 可以维护知识文档和知识片段。
- 可以根据客户问题检索商品、FAQ、售后规则和活动话术。
- 可以展示 AI 回复引用的知识来源。
- 可以记录 AI 调用日志、Token 使用量和调用耗时。
- 可以按自动化功能配置开启、暂停、关闭。
- 可以配置每项自动化功能的开始时间和结束时间。
- 可以配置每项自动化功能的适用工作号、单次上限和每日上限。
- 可以通过全视觉识别微信窗口、会话列表、聊天区和输入框。
- 可以通过动作序列执行鼠标点击、键盘输入、等待、校验和发送。
- 可以配置消息输入方式和发送触发方式。
- 可以在员工启动和监督下自动处理指定数量的好友申请。
- 可以生成欢迎语并在审核停顿后自动发送。
- 可以识别多个未读客户会话并加入单线程队列。
- 可以 OCR 识别客户问题并生成 AI 回复。
- 可以展示意图、置信度和风险等级。
- 可以按发送前审核停顿和最小发送间隔自动发送低风险回复。
- 可以提示高风险问题、停止自动发送并建议转人工。
- 可以通过按钮和快捷键暂停、停止或接管自动化任务。
- 可以查看问答记录和处理状态。
- 可以查看 RPA 任务、会话队列和动作日志。
- 可以生成朋友圈文案草稿。

### 12.2 质量验收

- 常见产品咨询能生成可直接参考的回复。
- 商品资料不足时不编造答案。
- 未命中可信知识来源时不得自动发送。
- FAQ 命中时优先使用标准答案。
- 售后规则命中时不得直接承诺退款、赔偿或补发结果。
- AI 调用失败、超时或结构化解析失败时不得自动发送。
- 退款、赔偿、投诉、差评威胁类问题能识别为高风险。
- 欢迎语和回复不包含明显违规承诺。
- 多个客户同时发消息时，系统能按单线程顺序处理，不并发发送。
- 每次消息发送前都能保留配置的审核停顿时间。
- 两次自动发送之间能满足配置的最小发送间隔。
- 消息发送前能校验目标会话和输入框内容。
- 鼠标点击、键盘输入和发送动作都能记录执行日志。
- OCR 低置信度、窗口焦点丢失、会话对象不确定时能停止任务。
- 员工能随时暂停、终止或人工接管自动化任务。
- 自动化功能关闭时，不扫描、不入队、不执行。
- 自动化功能暂停时，保留配置但不继续处理新任务。
- 当前时间超出生效时间段时，不允许启动自动化任务。

- 好友申请是否按单次任务上限自动通过并发送欢迎语。
- 客户消息是否完全依赖本地助手 OCR 读取可见消息。
- 发送前审核停顿默认设置为多少秒。
- 两次自动发送之间的最小发送间隔默认设置为多少秒。
- 单轮最多处理多少个未读会话。
- 紧急停止快捷键使用哪组按键。
- 商品资料、FAQ、售后规则第一版手动维护，还是支持 Excel 导入。
- 是否需要账号登录和员工权限。
- 是否需要主管端统计看板。
- AI 模型优先使用哪家供应商。
- 意图识别、回复生成、风险复核是否使用同一个模型。
- API Key 由系统统一配置，还是每个商家独立配置。
- MVP 知识检索先做关键词检索，还是直接做向量检索。
- 知识库是否需要支持有效期、审核状态和版本管理。
- 自动发送是否强制要求知识库命中。
- 是否需要从第一版开始支持向量检索。

## 17. 总结

本 MVP 聚焦个人微信工作号场景下的有人值守自动化客服效率提升，但不把脱离员工监督的无人值守自动化作为第一版目标。

推荐路线是：

```text
有人值守全视觉 RPA
↓
单线程多会话自动处理
↓
发送频率和审核停顿增强
↓
企业微信 / 微信客服官方接入
↓
低风险问题自动回复
```

这样可以先解决直播引流承接慢、产品咨询回复慢、话术不统一和员工机械操作多的问题，同时通过员工在岗监督、单线程队列、发送频率控制、审核停顿和异常停止，把误操作风险控制在可管理范围内。
